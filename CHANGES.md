# Сотрудники на телефоне: аккуратные карточки

На экране телефона строка сотрудника — компактная карточка без подписей «Сотрудник / Вахта / ИИН»: слева галочка, кружок с инициалами,
ФИО, должность, объект · отдел; справа «⋯»; ниже — вахта и овертайм. Кнопка «Открыть» на телефоне скрыта (открывается нажатием на ФИО),
ИИН на телефоне не показывается. Сводка-фильтры прокручиваются пальцем в одну строку; меню «📊 Excel» не вылезает за край экрана.

# Вкладка «Сотрудники»: новый компактный вид

- Таблица из 4 колонок вместо 9: **Сотрудник** (кружок с инициалами, ФИО, категория, 🔑 если есть логин; ниже — должность с «⚠»,
  ещё ниже — объект · отдел), **Вахта** (статус, даты, «осталось N дн.»; под ним овертайм — жёлтая плашка или неприметное «＋ овертайм»),
  **ИИН** (скрыт на узких экранах), справа — кнопка «Открыть» и меню «⋯» (Изменить карточку, Вахта, Овертайм, В отпуск, Уволить, Удалить).
  Колонки «Логин» и «Роль» убраны — в списке только сотрудники. Таблица больше не вылезает за край.
- Над таблицей — сводка-фильтры: 👥 Все · 👷 На вахте · 🏠 Дома · ❔ Вахта не указана · ⚠ Ошибки в должности (клик — фильтр).
- Восемь Excel-кнопок собраны в одно меню «📊 Excel ▾» (вахта / сотрудники и обучение / порядок в должностях).
- «Администраторы и ассистенты» — без изменений; «Архив» — в новом виде (статус вместо вахты, «Восстановить» + «⋯ Удалить»).

# Пометка «ошибка в должности» + санкнижки обновляются сами после замены должностей

- Сотрудники: у должности значок «⚠ проверить» / «⚠ не указана» (подсказка при наведении: нет в справочнике, не закреплена за
  отделом — и в каком отделе она есть, отдела нет в структуре). Кнопка-фильтр «⚠ Ошибки в должности (N)» показывает только таких.
  В карточке сотрудника — жёлтая плашка с причиной. Проверка по «Настройки → Объект → Отдел → Должность».
- «Порядок в должностях»: если у сотрудников новой должности уже есть санкнижки, должность сама отмечается
  «санкнижка обязательна» (период — какой чаще у их книжек), пометка «вне должности» снимается. Перезагружать файл санкнижек не нужно.

# Порядок в должностях: массовая замена из Excel

Сотрудники → «🔁 Порядок в должностях» (только суперадмин). Скачать текущие должности (объект / отдел / должность / сколько человек /
есть ли в справочнике), вписать «Новая должность» (и «Новый отдел»), загрузить → «Проверить» (ничего не меняет) → «Применить».
При замене: должность меняется у всех сотрудников с этой тройкой; новая добавляется в справочник и структуру отдела (если в справочнике
есть такая же другим регистром — берётся написание справочника); курсы по должностям и «санкнижка обязательна» переезжают на новую;
старая убирается из структуры отдела, если у неё не осталось сотрудников. Всё в одной транзакции, пишется в журнал действий.

- `routes/positionRemap.js` (новый), `Server.js`: `/api/positions/remap-template.xlsx`, `/api/positions/remap`.
- `index.html`: кнопка и окно «Порядок в должностях».

# Санкнижки: поиск сотрудников по латинице и перепутанным Фамилия/Имя

При загрузке санкнижек из Excel сотрудник теперь находится, даже если на сайте он записан латиницей
(«Daniyal Namazaliyev»), с перепутанными полями Фамилия/Имя, с казахскими буквами или без мягкого знака
(«Гулнара» = «Гульнара»). `routes/medbooks.js`: `skeletonFio`, поиск по «скелету» ФИО в обоих порядках.

# Ассистенты: разделы (дашборды) по зонам ответственности, без протоколов, «Выбрать все» в зоне

**Разделы ассистента.** В карточке ассистента (суперадмин → «Администраторы и ассистенты») появился блок
«Разделы (дашборды) ассистента»: БиОТ, Внутреннее обучение, Внешнее обучение, Мед. книжки — как у администраторов.
Ассистент видит и вносит только отмеченное и только по своей зоне (объекты / отделы). Пример: только «Мед. книжки» —
у ассистента «Главная» с дашбордом санкнижек, сотрудники и вахта; обучения, выгрузки и курсов нет.
Проверка — и в интерфейсе, и на сервере (каждый запрос).

**Миграция.** При первом запуске всем существующим ассистентам выдаются все разделы (ничего не пропадает),
дальше суперадмин снимает лишнее. Новые ассистенты создаются без разделов (видят только сотрудников и вахту).

**Протоколы.** Ассистенту закрыты: вкладка скрыта, сервер отвечает 403. Исключение — ассистент с ролью в комиссии
(председатель / инженер БиОТ / член): ему протокол нужен для подписи, он видит протоколы только своей зоны, как раньше.

**Главная для ассистента.** Если выдан хотя бы один раздел — у ассистента появляется «Главная» (дашборд) по его зоне.
Без курсовых разделов карточки курсов и «Просрочено и скоро истекает» скрыты; «Быстрые действия» ассистенту не показываются.

**Зона ассистента.** У списков «Объекты» и «Отделы» — кнопки «Выбрать все» и «Снять».

- `lib/adminFunctions.js`: `isLimitedRole` — функции проверяются у admin и assistant.
- `routes/auth.js`: для ассистента на каждый запрос из БД берутся также разделы и роль в комиссии.
- `routes/users.js`: суперадмин сохраняет разделы и ассистентам.
- `routes/protocols.js`: `noPlainAssistant` на всех маршрутах, где был допущен ассистент.
- `routes/courses.js` (`/stats/summary`), `routes/assignments.js` (`/expiring`): доступны ассистенту, строго по его зоне.
- `routes/medbooks.js`: объект/отдел вне зоны ассистента → пусто (а не «все»).
- `routes/trainingSessions.js`: проверка группы обучения по функциям — и для ассистента.
- `db.js`: однократная выдача разделов существующим ассистентам (`settings.assistant_functions_migrated`).
- `index.html`: блок разделов в карточке ассистента, разделы в списке, меню и главная ассистента, «Выбрать все».

# Санкнижки: загрузка из Excel и отметка должностей

«Главная → Личные мед. книжки → 📥 Загрузить из Excel». Колонки: Фамилия, Имя (или ФИО), ИИН, Допуск до, Период (мес.), Примечание.
Сотрудник ищется по ИИН, затем по Фамилии + Имени (без учёта регистра и казахских букв: Қалжанов = Калжанов).
Дата начала считается сама: «Допуск до» минус период. Галочка «Отметить должности» (админ/суперадмин) добавляет должности
найденных сотрудников в «Должности и периодичность» — книжка становится обязательной для всей должности, и остальные
сотрудники этих должностей появляются в списке со статусом «Дата не внесена». После загрузки — список ненайденных и замечаний.

- `db.js`: колонка `medbook_records.note` (примечание: ФГ, СМ, где проходил).
- `routes/medbooks.js`: `GET /api/medbooks/import-template.xlsx`, `POST /api/medbooks/import`; `PUT /user/:id` принимает `note`.
- `lib/medbook.js`: `note` в записях, экспорт `positionPeriods`.
- `index.html`: окно загрузки, поле «Примечание» в форме, примечание в таблице и карточке сотрудника, запись в журнале действий.

# Переключатель «Разделы сайта» для суперадмина (упрощённая версия без доступа к хостингу)

«Настройки → Разделы сайта» (только суперадмин): включить/выключить внутреннее обучение, внешнее обучение и мед. книжки.
Кнопка «Упрощённая версия: только БиОТ и санкнижки». БиОТ выключить нельзя. Выбор хранится в базе
(`settings.disabled_functions`), поэтому работает без доступа к Render; действует вместе с `ENABLED_FUNCTIONS`
(раздел включён, только если разрешён и там, и там). Изменение пишется в журнал действий.

- `db.js`: колонка `settings.disabled_functions` (JSONB, по умолчанию пусто — всё включено).
- `lib/adminFunctions.js`: `loadSiteFunctions`, `setDisabledFunctions`, кэш в памяти (перечитывается раз в минуту).
- `routes/settings.js`: `GET/PUT /api/settings/functions` (суперадмин).
- `Server.js`: загрузка разделов при старте. `index.html`: вкладка «Разделы сайта».
- `env.example`: добавлены SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, SUPABASE_BUCKET.

# Упрощённая версия: только БиОТ, санкнижки и вахта

Переменная окружения `ENABLED_FUNCTIONS` (см. env.example). `ENABLED_FUNCTIONS=biot,medbook` — внутреннее и внешнее обучение
отключены для ВСЕХ ролей, включая суперадмина: скрыты в меню, дашбордах, форме курса, списках курсов и групп, статистике,
выгрузках, «Моих тестах» сотрудника, публичной странице по QR и push-напоминаниях; сервер отвечает 403 на прямые запросы.
Без переменной всё работает как раньше. Данные в базе не удаляются и не меняются.

- `lib/adminFunctions.js`: `ENABLED_FUNCTIONS`, `isFunctionEnabled`, `enabledFunctions`, `siteKindSql`; проверки функций теперь
  учитывают включённые разделы для всех ролей.
- `routes/courses.js`, `routes/trainingSessions.js`: фильтр по виду курса — для всех ролей, а не только для админа.
- `routes/assignments.js` (/mine), `personService.js` (страница по QR), `lib/push.js` (напоминания), `routes/users.js` (импорт) — фильтр отключённых видов.
- `routes/settings.js`: `/api/settings/public` отдаёт `enabled_functions`; `index.html` скрывает отключённые разделы и не стирает
  выданные админам функции при сохранении карточки.

# Исправление: вахта не обновлялась после возвращения из дома

**Причина.** Статус «на вахте / дома» считался только по одной сохранённой вахте (заезд … отъезд). После отъезда
сотрудник навсегда оставался «дома», пока кто-то вручную не внесёт новую дату заезда. Цикл «вахта → дома → вахта»
был только в PDF-календаре, а в статусе — нет.

**Что сделано**
- `db.js`: новое поле `users.rotation_rest_days` — дней дома между вахтами. Пусто — как срок вахты (14/14, 28/28), 0 — разовая вахта без повтора.
- `routes/users.js`: статус, «осталось дн.», «заезд через N дн.», фильтр «На вахте / Дома» и выгрузка в Excel считаются по циклу —
  та же формула, что в PDF-календаре (`buildShifts`). В ответе `rotation_arrival / rotation_departure` — текущая или ближайшая смена,
  сохранённые даты — в `rotation_anchor_*`. Excel: колонка «Дома (дней)» в бланке, выгрузке и загрузке. PDF по умолчанию берёт сохранённые «дома».
- `index.html`: в окне «Вахта» поле «Дома между вахтами (дней)» (сохраняется); в карточке сотрудника — строка «Дома: N дн.».
- Существующим сотрудникам ничего вносить не нужно: у них «дома» = срок вахты, и статус сразу начинает считаться по кругу.

# Функции администраторов (БиОТ / внутреннее / внешнее обучение / мед. книжки)

Суперадмин выдаёт каждому администратору одну или несколько функций. Админ работает только с тем, что ему выдано;
всё остальное скрыто в интерфейсе и закрыто на сервере (проверка идёт на каждый запрос, по данным из БД).

- `БиОТ` — наши курсы с тестом (course_kind = internal), назначения, протоколы, удостоверения, сертификаты.
- `Внутреннее обучение` — курсы «без протокола» (no_protocol) и группы обучения по ним.
- `Внешнее обучение` — внешние курсы (external) и группы по ним.
- `Мед. книжки` — раздел мед. книжек (должности, периодичность, записи сотрудников).

**Миграция.** При первом запуске в БД появляется `users.admin_functions`, и всем уже существующим админам выдаются ВСЕ четыре
функции (ничего не пропадает). Новые админы создаются без функций, пока суперадмин их не отметит. Суперадмин и ассистент не затронуты.

**Сервер:** `lib/adminFunctions.js` (константы, проверки, middleware), `routes/auth.js` (`/api/auth/me`, функции в токене/логине),
`routes/users.js` (поле `admin_functions`, только суперадмин), `courses.js`, `assignments.js`, `protocols.js`, `trainingSessions.js`,
`bulkTraining.js`, `coursePositions.js`, `medbooks.js`, `export.js`.
**Интерфейс:** чекбоксы в карточке администратора, функции в списке «Администраторы и ассистенты», скрытие вкладок,
дашбордов и видов курса в форме курса.

# Исправление: «На экран Домой» открывает сайт, а не приложение

**Причина.** `manifest.webmanifest` ссылался на `/icons/icon-512.png`, `/icons/maskable-192.png`, `/icons/maskable-512.png`,
а на сервере их не было (в репозитории лежал только `icon-192.png`, и не в `assets/icons/`, а в `assets/fonts/icons/`).
Без иконки 512x512 Chrome не считает сайт устанавливаемым приложением и добавляет обычную закладку.

**Что сделано**
- `assets/icons/`: созданы `icon-192.png`, `icon-512.png`, `maskable-192.png`, `maskable-512.png`; добавлены `apple-touch-icon.png`, `favicon-*`.
- `public/manifest.webmanifest`: иконки приведены в соответствие с файлами.
- `Server.js`: `/icons` отдаётся и из `assets/fonts/icons/` (запасной путь), чтобы ошибка с папкой не повторилась.

**После выкладки на телефоне:** удалить старый ярлык с экрана «Домой», открыть сайт в Chrome (Android) / Safari (iPhone) и добавить заново.
