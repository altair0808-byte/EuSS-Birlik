# Исправления (24.09.2026, вторая итерация)

## Ошибки
1. **«Статистика по курсам — Произошла ошибка»** — `routes/courses.js`, `GET /stats/summary`:
   `next_test_date` в БД хранится как TEXT, а сравнивалась с `NOW()` без приведения типа →
   PostgreSQL: `operator does not exist: text < timestamp with time zone`. Добавлено `::timestamptz`.
2. **Не работают «Изменить», вкладки курсов в статистике, выбор сотрудника при назначении** —
   `db.js`: драйвер `pg` отдаёт BIGINT-id строкой ("12"), а `index.html` сравнивал строго с числом.
   Теперь int8 → число (`types.setTypeParser(20, …)`); в `index.html` сравнения id дополнительно
   сделаны через `String(...)`.
3. **«Добавить сотрудника» «не нажимается»**:
   - кнопка на главной («Быстрые действия») только переключала вкладку — теперь открывает форму
     (`quickAddUser`, аналогично `quickAddCourse` для «Создать курс»);
   - ошибка сервера при сохранении терялась молча — теперь показывается сообщение, кнопка «Сохранить»
     блокируется на время запроса;
   - `POST /api/users` теперь сохраняет «№ сертификата» (раньше игнорировал при создании);
   - `loadUsersList` показывает ошибку вместо вечной «Загрузки…».

## Новое: блок «Скоро истекает» на главной
Поиск (ФИО/курс/объект/отдел/должность), период (30/60/90/180/365 дн.), статус (просрочено / ≤7 / ≤14 / ≤30 дн.),
фильтры по курсу и объекту, сортировка (срочные ↔ дальние, ФИО А–Я/Я–А, курс, объект),
счётчик «Показано X из Y», «Сбросить фильтры», выгрузка отфильтрованного списка в CSV.

# Третья итерация (24.09.2026)

## Единый фильтр «Объект / Отдел» на всех вкладках
- Строка фильтра сверху на вкладках «Главная», «Сотрудники», «Курсы», «Назначения», «Протоколы», «Календарь».
  Выбор запоминается на время сессии и действует на всех вкладках сразу; после выбора объекта список отделов
  сужается до отделов этого объекта; кнопка «Сбросить».
- Что именно фильтруется: главная (счётчики, статистика по курсам, «Скоро истекает»), сотрудники, курсы
  (счётчики «не прошли обучение» и список сотрудников), назначения, протоколы (только протоколы, где есть
  сотрудники выбранного объекта/отдела), календарь.
- Прежние отдельные выпадающие списки объекта/отдела на вкладках «Сотрудники» и «Назначения» и в блоке
  «Скоро истекает» убраны — вместо них общая строка.
- Бэкенд: параметры `object` / `department` добавлены в `GET /api/courses`, `/api/courses/stats/summary`,
  `/api/courses/:id/untrained`, `/api/assignments/expiring`, `/api/protocols`; `/api/users/meta/objects`
  теперь отдаёт ещё и пары «объект → отдел».

## Новый экспорт в Excel (routes/export.js + окно «Экспорт в Excel»)
- Окно настройки: объект, отдел, курс, статус, срок действия, период даты прохождения, сортировка
  (объект→отдел→ФИО / ФИО / объект / отдел / курс / дата прохождения / следующее прохождение),
  «Разделить по листам» (по объектам / отделам / курсам), «только последняя запись по курсу».
- Файл: лист «Сводка» (параметры выгрузки, показатели, таблицы по объектам / отделам / курсам)
  + лист(ы) журнала с колонками «Дата прохождения», «Следующее прохождение (действителен до)»,
  «Осталось дней» (формула от сегодняшней даты, цветная подсветка), результат, сертификат, протокол.
- Оформление: цветная шапка, закреплённая шапка и колонка ФИО, полосатые строки, цветные статусы,
  автофильтр Excel на каждой колонке, счётчик «Показано записей» (учитывает фильтр), печать на A4 в альбомной ориентации.
- Даты — настоящие даты Excel (dd.mm.yyyy), часовой пояс по умолчанию Asia/Almaty (переменная `EXPORT_TZ`).
- Кнопка «Скачать отчёт» в карточке сотрудника теперь выгружает только этого сотрудника (раньше — весь журнал).

## Исправление логики «просрочено»
Если сотрудник пересдал курс, старая запись с истёкшим сроком больше не считается просрочкой:
срок оценивается только по последней успешной записи по каждому курсу — в «Скоро истекает», в счётчиках
главной, в статистике по курсам и в Excel (старые записи помечены «архив»).
